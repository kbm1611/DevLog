# 검증 체크리스트

작업 완료를 보고하기 전에 이 체크리스트를 확인한다.

## Build And Test

- [ ] 코드 변경 전에 실패해야 하는 테스트를 먼저 작성했다.
- [ ] RED 단계에서 테스트가 기대한 이유로 실패하는 것을 확인했다.
- [ ] GREEN 단계에서 최소 구현으로 같은 테스트가 통과하는 것을 확인했다.
- [ ] 리팩터링을 했다면 테스트 통과 후에만 수행했고, 이후 테스트를 다시 실행했다.
- [ ] 백엔드 변경이 있으면 다음 명령을 실행했다.

```powershell
cd backend
.\gradlew.bat build
```

- [ ] 빌드가 성공했다.
- [ ] 테스트 실패가 없다.
- [ ] 실패가 있다면 실패 로그와 원인을 사용자에게 보고했다.
- [ ] 프론트엔드 변경이 있으면 다음 명령을 실행했다.

```powershell
cd frontend
npm run build
```

- [ ] 프론트엔드 빌드가 성공했다.
- [ ] 테스트를 생략한 코드 변경이 있다면 이유와 대체 검증 방법을 사용자에게 보고했다.

## Structure

- [ ] 새 파일이 `02-file-structure-contract.md`의 허용 구조 안에 있다.
- [ ] 새 패키지를 만들었다면 구조 예외 절차를 따랐다.
- [ ] 기존 파일 이동이나 패키지 이동이 있었다면 `07-decision-log.md`에 기록했다.

## Documentation

- [ ] `AGENTS.md`의 진입 규칙과 충돌하지 않는다.
- [ ] 하네스 문서 목차와 링크가 실제 파일과 맞다.
- [ ] 구조, 워크플로, 검증 방식이 바뀌었다면 관련 하네스 문서를 갱신했다.
- [ ] 예상하지 못한 테스트, 빌드, 검증 실패를 수정했다면 `08-failure-fix-log.md`에 기록했다.

## Final Response

- [ ] 생성 또는 수정한 주요 파일을 요약했다.
- [ ] 실행한 검증 명령과 결과를 적었다.
- [ ] 실패 수정 로그를 기록했다면 항목 제목을 적었다.
- [ ] 실행하지 못한 검증이 있으면 이유를 적었다.
