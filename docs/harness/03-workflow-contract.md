# 작업 흐름 계약

이 문서는 AI 작업자가 요청을 처리할 때 따라야 하는 최소 작업 흐름을 정의한다.

## Before Editing

작은 변경이라도 수정 전에 다음을 정리한다.

- 변경 목표.
- 변경 범위.
- 수정할 파일.
- 새로 만들 파일.
- 검증 명령.
- 관련 하네스 문서 갱신 필요 여부.

## Feature Work Flow

1. `04-feature-spec-template.md`를 기준으로 기능 스펙을 작성하거나 사용자 요청에서 같은 정보를 확인한다.
2. `05-implementation-plan-template.md`를 기준으로 구현 계획을 작성한다.
3. `02-file-structure-contract.md` 안에서 해결 가능한지 확인한다.
4. 테스트 또는 검증 기준을 먼저 정한다.
5. 계획된 파일만 수정한다.
6. `06-verification-checklist.md`로 완료 여부를 확인한다.

## Bug Fix Flow

1. 증상과 재현 조건을 정리한다.
2. 관련 테스트가 있으면 먼저 실행한다.
3. 원인을 확인하기 전에는 추측성 수정으로 넘어가지 않는다.
4. 최소 범위로 수정한다.
5. 재현 시나리오와 전체 빌드를 검증한다.

## Documentation-Only Flow

1. 문서의 독자와 목적을 확인한다.
2. 기존 문서 구조와 링크를 확인한다.
3. 새 문서가 하네스 흐름에서 어디에 연결되는지 명확히 한다.
4. 코드 변경 없이 문서만 수정한다.
5. 링크, 목차, 경로가 실제 파일 구조와 맞는지 확인한다.

## Completion Rule

작업 완료 보고에는 다음 내용을 포함한다.

- 생성 또는 수정한 주요 파일.
- 실행한 검증.
- 남은 위험이나 실행하지 못한 검증.
